# 加载诊断（不恢复短信）0.1.0

这是独立的兼容性诊断包，用来解释原版扩展为什么看起来「无效」。它不恢复 Google 短信，也不保证任何国家或地区的号码可用。

原版 `v1.1.0` 目录保持不动。不要把本目录里的文件覆盖进原版目录。

## 实际对上的客户端问题

原版清单没有工具栏按钮。`content.js` 只在下面两种页面创建面板：

- 主机名正好是 `console.cloud.google.com`
- 路径包含 `/challenge/iap/qrcode`

其他已注入的账号页会执行到开头就返回，页面上没有任何说明。用户只能看到验证页仍在，无法区分「脚本没加载」「当前路径本来就不显示面板」和「服务端仍要求原来的验证方式」。

## 这个包做什么

- 提供工具栏入口。点开后只用固定说明文字报告当前判断。
- 角标 `HID`：诊断脚本已在此页运行，但原版不会显示面板。
- 角标 `UI`：原版会显示它自己的面板。本包没有替你完成验证。
- 没有角标：诊断脚本没有注入。
- 不声明 `g.co` 权限，不跟随短链接。

本包没有网络请求，没有请求头或设备标识修改，没有验证码降级，也没有遥测。页面地址的查询串不会显示，也不会写入扩展存储。

## 安装

1. 校验压缩包：在仓库根目录执行 `sha256sum -c dist/SHA256SUMS.txt`。
2. 解压 `dist/qr-helper-load-diagnostics-0.1.0.zip`。
3. 打开 `chrome://extensions`，打开开发者模式。
4. 选择「加载已解压的扩展程序」，选中解压后的 `load-diagnostics` 目录（该目录里直接有 `manifest.json`）。
5. 在工具栏固定「加载诊断（不恢复短信）」。不要加载成原版目录。

若原版「Google QR 自动降级短信助手」仍处于启用状态，它自己的行为还在。本包不会停用其他扩展。想确认当前浏览器没有原版的自动动作时，请在同一页停用或移除原版，只保留本诊断包。

## 移除

在 `chrome://extensions` 找到「加载诊断（不恢复短信）」，选择移除。这不会移除原版；原版需要单独移除。

## 怎样读结果

打开要查看的页面，看工具栏角标，再点开图标。弹出窗口的三段文字分别是：页面判断、诊断脚本是否已回报、本包不会发送网络请求也不会恢复短信。

`HID` 对应原版会静默退出的账号页。这能说明「无效」至少有一种来自界面根本没有挂出来，而不是本包已经恢复了短信。

## 测试

在仓库根目录执行：

```bash
node --test tests/load-diagnostics/*.test.mjs
```

覆盖范围：

- 用合成地址复现原版 `content.js` 的挂载条件：二维码路径和 Cloud Console 会挂面板，其余账号路径不会。
- 诊断分类与该挂载条件一致，并覆盖非 https、短链接、声明站点之外的页面。
- 渲染结果不包含合成查询串、用户信息或路径里的伪 token。
- 清单权限是原版主机权限的子集，没有新增主机，没有声明式网络规则，没有工具栏以外的自动动作入口。
- 诊断源码不包含网络请求或标识伪装。
- 打包结果与 `dist/SHA256SUMS.txt` 一致，压缩包内没有原版脚本。

这些测试在本地用合成数据完成。它们不是 Google 验证成功，也没有在 Mac Chrome 157 上加载。

## 未验证的范围

- 没有在 Mac 或 Chrome 157 上安装或启用。之后要看真实浏览器里的角标和弹窗，需要你在自己的 Mac 上加载本诊断包。
- 没有访问 Google 账号、登录页、验证接口或短信。
- 不能据此判断服务端是否仍要求二维码、设备验证或手机号验证。
- 原版里已有的 token 提取、身份接口调用、请求头伪装和验证降级都没有移植，也没有改进。

若加载本包后仍无法对应你看到的现象，只需补充这三项非敏感信息：扩展卡片上的红色错误原文、角标是 `HID`、`UI` 还是没有、弹出窗口里的全文。不要发送二维码、页面查询串、Cookie、token、手机号或验证码。
